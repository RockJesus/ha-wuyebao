# 物业宝 Home Assistant 集成（wuyebao）

[![HACS Default](https://img.shields.io/badge/HACS-Default-orange.svg)](https://hacs.xyz/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

Home Assistant 自定义集成（集成域名 `wuyebao`），用于连接物业宝 App，实现门禁控制等功能。

> 仓库：https://github.com/RockJesus/ha-wuyebao

## 功能特性

- ✅ 用户名密码登录（client_id 与 App 对齐）
- ✅ Token 自动刷新（长期有效，突破7天限制）
- ✅ 门禁设备列表自动发现（**返回小区全部门**：南门、北门 + 各楼栋单元门口机，按楼栋/单元正确命名；实体按稳定 gate id 注册，更新不会删除已有门）
- ✅ 门锁实体（每个门禁一个实体，共 26 个门）
- ✅ SIP 开门（南门、北门、单元门均正常）
- ✅ 最近访客摄像头实体（每个门口机一个，显示最后一次访客按门铃的抓拍照片，附访客时间属性）
- ✅ **实时视频流**（内置 RTSP 服务器，支持 go2rtc / ffmpeg 拉流观看监控，南门/北门/单元门均可实时观看；**自动续流**——画面中断自动重建会话）
- ✅ 实时监控摄像头属性直接显示 RTSP 地址（v6.6.8 起，"流地址"传感器已移除，RTSP 地址见"实时监控"摄像头属性）
- ✅ 传感器：用户名、小区信息
- ❌ 电梯呼叫（暂不支持）
- ❌ 查看监控按钮（v6.6.6 起移除，实时监控直接由摄像头实体提供）
- ❌ 流地址传感器（v6.6.8 起移除，RTSP 地址在"实时监控"摄像头实体的属性中）

## 安装

### 方法一：HACS 安装（推荐）

1. 确保已安装 [HACS](https://hacs.xyz/)
2. 在 HACS 中搜索 "物业宝" 或 "wuyebao"
3. 点击下载并重启 Home Assistant

### 方法二：手动安装

1. 下载 `custom_components/wuyebao/` 文件夹
2. 将其复制到 Home Assistant 的 `custom_components/` 目录
3. 重启 Home Assistant

## 配置

1. 在 Home Assistant 中，进入 **设置** > **设备与服务**
2. 点击 **添加集成**
3. 搜索 "物业宝"
4. 输入手机号和密码
5. 点击提交

## 实体说明

### 门锁实体

每个门禁设备会自动创建一个门锁实体：

- **名称**：根据设备别名/楼栋单元自动命名（如"南门"、"4栋1单元"）
- **状态**：始终显示锁定，解锁后 10 秒自动恢复锁定
- **解锁**：调用 `lock.unlock` 服务发送开门指令

**属性**：
- `device_id` - 设备 ID
- `device_type` - 设备类型（outdoor/wall）
- `unlock_password` - 开门密码
- `sip_target` - SIP 目标地址

### 传感器实体

- **用户名** - 当前登录账号
- **小区** - 所在小区名称

### 摄像头实体

每个带摄像头的门禁设备（围墙门、门口机）会自动创建两个摄像头实体：

**最近访客摄像头**
- **名称**：根据设备别名/楼栋单元自动命名（如"南门最近访客"、"4栋1单元门口机1最近访客"）
- **图像**：显示该门禁设备**最后一次访客按门铃后的抓拍照片**（呼叫记录严格按设备号匹配，不会串图）
- **属性**：`最近访客时间`（该抓拍记录的生成时间）、`gate_id`、`device_number`
- **挂载**：与门锁实体挂载在同一设备下

**实时监控摄像头（实时视频流）**
- **名称**：如"南门实时监控"、"4栋1单元门口机1实时监控"
- **机制**：集成内置 RTSP 服务器，通过 SIP INVITE 建立监控会话，H264 RTP 流经内置 RTSP 服务器转发（`rtsp://127.0.0.1:8556/<gate-id>`）
- **go2rtc 集成**：在 go2rtc 配置中添加摄像头属性中的 `rtsp_url`（`rtsp://127.0.0.1:8556/<gate-id>`）源即可转 WebRTC 实时观看（v6.6.8 起 RTSP 地址位于该实体属性，不再有独立"流地址"传感器）
- **自动重试**：无媒体时自动挂断重试（最多 5 次，退避 4/6/10/15s），设备忙（486）时自动等待设备释放会话后重拨
- **自动续流**：门口机约 30s 后停止推流导致画面冻结时，看门狗自动检测静默并重建监控会话，持续观看无需手动操作
- **NAT 打洞**：自动复制 App 的 "probing data" + RTCP 打洞机制打通媒体通道（0.5s 持续打洞）

**工作原理**：
1. 登录后获取业主信息（含室内机 `bindingCode`）
2. 调用呼叫记录接口获取该室内机收到的门口机呼叫记录
3. 按设备号严格匹配呼叫记录中的 `imageUrl`（阿里云 OSS 抓拍图）
4. 摄像头实体展示匹配的最新抓拍图
5. 实时视频流：RTSP 客户端拉流时，集成通过 SIP REGISTER → INVITE 建立与门口机的监控会话，收到 H264 RTP 后转发给 RTSP 客户端

**说明**：
- 单元门口机（outdoor）有呼叫记录，最近访客/实时监控均可正常显示
- 南门/北门（wall）如无呼叫/报警记录，摄像头显示"不可用"（不会错误显示其他门的图像）
- 可在物业宝 App 中按铃呼叫单元门口机，生成新的抓拍记录

**属性**：
- `gate_id` - 门禁设备 ID
- `device_number` - 设备号（a=南门、b=北门、数字=门口机）
- `rtsp_url` - RTSP 实时流地址（实时监控摄像头）
- `最近访客时间` - 最近访客抓拍记录时间（最近访客摄像头）

## API 说明

本集成基于物业宝 App 抓包分析，主要接口：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/client/anon/token` | POST | 登录获取 Token（请求头需带 App 的 client_id） |
| `/api/client/anon/refresh_token` | GET | 刷新 Token |
| `/api/client/anon/client_token` | GET | 获取 SIP Token |
| `/api/device/grant/gates` | GET | 获取门禁列表（按 communityId+unitId+type=indoor 过滤，只返回本单元设备） |
| `/api/owner/anon/owners/community` | GET | 获取业主信息 |
| `/api/owner/grant/owners` | GET | 获取业主详情（含室内机 bindingCode、unitId） |
| `/api/call/{page}/{size}/grant/calls` | GET | 获取呼叫记录（含门口机抓拍图） |

## 更新日志

### v6.7.3
- **修复除南门以外所有门（北门/单元门）实时监控看不了**
  - 根因：看门狗静默阈值固定 10s，而单元门/北门设备应答 INVITE 后需 10-30s 才推流 → 会话在设备推流前就被误杀重建，循环无画面
  - 修复：①看门狗按会话媒体状态分档——**从未出过媒体**的会话容忍 60s（耐心等设备首帧），**已出过媒体**后静默才按 10s 重建（续流）；②会话建立时 `wait_for_video` 25s→60s，覆盖设备最长推流延迟；③空闲保留也分档——未出媒体会话保留 120s（预热+重连复用），已出媒体会话关闭后 15s 释放
  - 南门、北门、全部单元门口机实时监控统一走同一逻辑

### v6.7.2
- **实时监控按需请求：只在点击实时监控时发请求，关闭后立即停止**
  - 之前：关闭监控后会话仍保留 120s（重连复用），期间若客户端重连会持续触发 SIP 请求；看门狗遇静默流会无限重建会话
  - 现在：①客户端显式 TEARDOWN（停止播放）→ 立即停止 SIP 会话（BYE），不再保留；②客户端直接断连（无 TEARDOWN）→ 15s 内允许短暂重连复用，超时立即 BYE；③看门狗重建加冷却（60s 窗口内同一门最多 4 次），杜绝异常重连导致的持续请求
  - 平时无任何 RTSP 客户端连接时完全静默，不发任何 SIP/API 请求

### v6.7.1
- **修复：集成重新加载/删除无响应（unload 卡死）**
  - 根因：RTSP 服务器 `stop()` 的 `wait_closed()` 会等待所有活动连接 handler 结束；监控播放中客户端连接永久阻塞在 recv → `async_unload_entry` 永远不返回
  - 修复：服务器关闭时强制关闭所有活动 RTSP 客户端连接，`wait_closed()` 加 5s 超时；DESCRIBE/PLAY 后台建会话任务纳入跟踪并在 shutdown 时取消

### v6.7.0
- **实时监控：北门/单元门看不了 → 复刻南门逻辑**
  - 根因：南门设备应答后立即推流，通过 5s 媒体确认；北门/单元门应答后 10-30s 才推流，被 5s 确认窗误判为"无媒体"反复重试，永远建不成会话
  - 媒体确认窗 5s → 15s（强流 ≥40 包仍提前退出）；应答等待 25s → 15s；INVITE 重试 6 次 → 8 次（间隔 1.5s）；外层 backoff 缩短；wait_for_video 20s → 25s
  - RTSP 侧：DESCRIBE/PLAY 有界等待（各 25s，任务 shield 保护后台继续建会话）；首次连接作为预热，客户端自动重连即可直接出画面；空闲会话保留 30s → 120s，重连立即复用
- **最近访客串图修复**
  - 根因：call 记录里所有单元门口机 `deviceNumber` 都是 "1"（非唯一），且 API 用用户绑定码 callNumber 过滤导致只返回自家单元的记录
  - 移除 callNumber 过滤（返回全小区各门记录），匹配改为 unitId 强匹配 → buildingId+deviceNumber → wall 门（a/b 唯一）保底，各门各图不再串

### v6.6.9
- **修复删除集成/实体卡住（unload_in_progress）**：视频管理器 shutdown 不再无限等待锁和后台会话重建任务——锁获取 3s 超时、会话停止 15s 超时、重启任务随看门狗一并取消，删除集成/实体可正常完成
- **删除 info.md**（HACS 说明并入 README，安装包不再包含该文件）

### v6.6.8

- **修复北门/单元门实时监控状态来回跳**：外层重试退避由 10/20/30/45s 缩短为 **4/6/10/15s**（总窗口 ~105s → ~35s），RTSP 客户端（go2rtc/HA 播放器）不再因等待超时反复断开重连；会话建立后空闲保留 30s 供快速重连复用
